Fix: Odoo asset routing through passthrough proxy

Problem: Odoo static assets (/web/assets/*, /web/manifest.webmanifest) were
returning 404 from Django instead of being proxied to the upstream Odoo server.

Root cause: When Odoo's HTML is served, the browser makes relative requests to
paths like /web/... which don't start with /pt/admin/{trigger}/, so they miss
the passthrough URL pattern and hit Django's default 404 handler.

Solution (two-part):

1. **URL Rewriting in OdooPassthroughHandler.process_html_response()**
   - Rewrite asset paths in HTML responses to include proxy prefix
   - Regex patterns for /web/assets/, /web/images/, /web/webclient/, /web/manifest.webmanifest
   - These rewritten URLs now route through the proxy correctly

2. **Catch-all Routing for Orphaned /web/* Requests**
   - Added new URL pattern: path('web/<path:subpath>/', odoo_stray_web_request_view)
   - New view: odoo_stray_web_request_view() in admin_views.py
   - Looks up current tenant's Odoo endpoint from TenantApp
   - Proxies the request directly to upstream Odoo
   - Handles cases where browser makes direct /web/* requests

This ensures all Odoo assets and API calls route correctly to the upstream
server, regardless of whether they're embedded in HTML or requested directly.
