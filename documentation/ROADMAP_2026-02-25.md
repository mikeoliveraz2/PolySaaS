# PolySaaS Roadmap — February 25, 2026

## Active Tracks (no priority order)

### Track 1 — Subscription Bundle Selection & Pricing
Update the subscription flow to let users select which bundled apps they want before going to Stripe.

**Pricing tiers:**
- 1 app: $29/user/month
- 3 apps: $49/user/month
- Unlimited: $99/user/month

**Requirements:**
- App selection UI in the subscribe page (before Stripe checkout)
- Price calculation based on selection
- On successful payment, auto-provision user accounts in each selected app
- Tenant record stores which apps are enabled

### Track 2 — OAuth2 SSO for All Bundled Apps
Django becomes the OAuth2/OIDC provider (via `django-oauth-toolkit`). All bundled apps authenticate through Django so users get seamless single sign-on.

**Apps:** Odoo, Mattermost, Liferay CE, Nextcloud, Dolibarr, WordPress, Monitor Logger

**Requirements:**
- Django as OAuth2 provider issuing tokens
- Each app configured as OAuth2 client
- Subscription auto-provisions accounts in selected apps via their APIs:
  - Nextcloud: OCS User Provisioning API
  - Odoo: XML-RPC create res.users
  - Mattermost: REST API create user + team
  - Liferay: REST API create user
  - WordPress: REST API create user
  - Dolibarr: REST API create user
  - Monitor Logger: Django-managed (internal)
- User clicks app in PolySaaS menu → seamless OAuth2 login, no second credential entry

**Key coupling:** Track 1 (subscription) creates the accounts, Track 2 (OAuth2) enables SSO login.

### Track 3 — Proxy Handler Generation (from PolySniffer captures)
Analyze TrafficLog entries from PolySniffer to generate proxy handler Python modules.

**Flow:**
1. PolySniffer captures raw traffic (done, working)
2. AI analyzes URL patterns, methods, headers, auth tokens, request/response shapes
3. Generates a Python handler module the passthrough proxy can load
4. Handler is saved and registered with the PassThroughEndpoint

**Existing wiring:** `ai_analyze_endpoint` and `ai_generate_handler` URL routes exist in `dose/polysniffer/urls.py`.

### Track 4 — OpenAPI Spec Generation (from captures)
Parse captured requests/responses into OpenAPI 3.0 specifications.

**Requirements:**
- Group captures by path pattern
- Extract URL parameters, query strings, headers
- Infer request/response schemas from captured bodies
- Output `.yaml` or `.json` OpenAPI spec per endpoint
- Could produce dozens of operations per endpoint depending on capture volume
- Viewable in Swagger UI alongside the existing Dose API docs

### Track 5 — Liferay Portlet Generation
Generate a Liferay portlet for each sniffed endpoint.

**Requirements:**
- Portlet is fed by the PolySaaS proxy (not direct to the raw endpoint)
- Proxy handler from Track 3 must exist first
- Portlet is a thin frontend rendering proxy responses inside Liferay's portal
- One portlet per endpoint — scoped to that endpoint only
- Decision pending: Java-based portlet vs web component/iframe portlet
