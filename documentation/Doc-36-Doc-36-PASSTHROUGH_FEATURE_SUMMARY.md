# Passthrough Feature Summary

## Overview
This document summarizes the implementation and workflow of the passthrough endpoint feature in DoseV3MasterSaaS as of October 2, 2025.

## Key Features
- Middleware intercepts unmatched requests and proxies them to external endpoints based on exact path matching.
- Admin UI allows configuration of passthrough endpoints with tooltips and validation.
- All schemas are migrated to support passthrough endpoints.
- Catchall view removed from URLconf to allow middleware to handle unmatched paths.
- External responses (HTML) are mapped so all links and form actions route back through the passthrough endpoint.
- Mapped HTML is stored in the `CallBackData` table and served via a loader page that fetches content by callback id.
- Hop-by-hop headers are excluded from proxied responses to prevent server errors.

## Workflow
1. Request to an unmatched path (e.g., `/dose/osticket/`) triggers the middleware.
2. Middleware checks for an enabled passthrough endpoint with an exact path match.
3. If matched, the request is proxied to the external service, and the response is processed:
   - All links/forms in HTML are rewritten to route through the passthrough endpoint.
   - The mapped HTML is saved in `CallBackData`.
   - A loader page is returned, which fetches the HTML from `/dose/callbackdata/<id>/`.
4. The loader page displays the proxied content to the user.

## Error Handling
- External errors (e.g., target down) are displayed as returned by the external service.
- Middleware excludes hop-by-hop headers to avoid WSGI assertion errors.

## Files Modified
- `mysite/external_passthrough_middleware.py`: Middleware logic, HTML mapping, callback storage, header filtering.
- `dose/views/callbackdata.py`: View to serve HTML from `CallBackData`.
- `dose/urls.py`: URL pattern for callback data loader.
